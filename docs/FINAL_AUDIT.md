## Exclusions and limits

LeakSanitizer is unsupported on this macOS runtime, so leak detection was disabled
while ASan/UBSan passed. Linux and hosted macOS CI are configured but unobserved.
The extended 2,016-case profile was not run; the optional million-row profile is
disabled. Fuzzing is bounded deterministic mutation; PMR injection covers selected
accounted allocation prefixes, not every process allocation. No whole-process
leak-freedom, production readiness, exhaustive SQL correctness or external-engine
performance claim is made. Memory limits/peaks are accounted scopes, not RSS caps.

The SQL surface remains explicit and restricted; no external query fallback,
extra joins/types/functions, GUI, storage extensions, publishing, pushes, tags,
commits, destructive cleanup or global installation were added. Exact commands,
raw paths, historical failed diagnostics and next action are in
[VERIFICATION.md](VERIFICATION.md) and [CHECKPOINT.md](CHECKPOINT.md).

The last finding came from core-owner self-review. Its correction was inspected
independently. Fixed-capacity reservation keeps descriptor pointers valid through
the query; catalog and group strings outlive borrowed vectors, and sink Values
own returned bytes. Native regressions also exercise results after Engine
destruction and account restoration after failures.

Conservative pushdown disables the whole transformation when any WHERE subtree
can fail. This matters even for apparently literal comparisons such as
`l.id > -(-9223372036854775808)`: moving it below an inner join could evaluate it
on unmatched rows; pushing a FALSE sibling first could suppress its required
eager error. Failed constant folds retain their original evaluation site.
DOUBLE accumulation order constrains swaps even when approximate oracle
comparison might otherwise hide a change.
